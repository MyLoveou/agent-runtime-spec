# 项目装配单

> 每个业务仓记一份「它到底拿了哪些规则 / Skill / Agent」。
> **只写名字，不存内容**：资产仍然只有三个平台目录各一份。

## 为什么不是「再复制一份」

历史上做过 `domains/`（内容副本 + manifest + 搬运脚本），被 D-20261106-01 删掉了：那是第 4 份副本，改一处要改四处，还得维护脚本。

这里的装配单是**档案**，不是**构建**：

| 它做 | 它不做 |
|------|--------|
| 记录某个项目启用了哪些资产 | 复制资产内容 |
| 让「本仓改了什么会影响谁」有据可查 | 生成 / 同步业务仓 |
| 新项目开工时给出拷贝清单 | 让运行时跨目录引用 |

## 目录约定

```
projects/
├─ _template/            # 复制这个建新项目（校验会跳过 _ 开头的目录）
│  ├─ README.md
│  └─ assembly.json
└─ <项目名>/
   ├─ README.md          # 这个项目是什么、为什么这么装配、当前状态
   └─ assembly.json      # 机器可读的装配单
```

## 字段

| 字段 | 必填 | 说明 |
|------|:---:|------|
| `project` | ✓ | 必须等于目录名 |
| `role` | | 一句话定位（写给人看） |
| `platforms` | ✓ | `cursor` / `opencode` / `dsh` 的子集 |
| `stack` | | 技术栈标签，仅用于阅读 |
| `rules.include` | | 规则名或通配（只支持 `*`，如 `vue-*`） |
| `rules.exclude` | | 从 include 里剔除，展开后不得与 include 相交 |
| `skills` | | Skill 目录名 |
| `agents` | | Agent 名（平台不支持 Agent 时忽略） |
| `entry` | | 业务仓要额外拷的入口文件，如 `AGENTS.md`、`docs/` |
| `notes` | | 特殊约定，一两句 |

## 怎么用

1. **新建项目**：复制 `_template/`，改目录名与 `assembly.json`；
2. **开工**：按清单把资产从对应平台目录拷进业务仓——用显式命令按名字过滤，不要整目录一把拷；
3. **本仓改动后**：跑一次校验，装配单里失效的引用会直接报错。

```powershell
# 从平台目录根执行（三个平台的相对路径一致）
skills/spec-check/scripts/check-spec.ps1
```

## 校验会查什么

- `assembly.json` 可解析；`project` 与目录名一致；
- `platforms` 只能是那三个；
- `include` 里每个通配至少展开出一条规则；`include` 与 `exclude` 展开后不得相交；
- `skills` / `agents` 的名字必须在三个平台都存在（不存在即报错，避免资产改名后清单失效）；
- 目录里必须有 `README.md`。

## 边界

- **不生成、不同步、不自动改写业务仓**：拷贝仍由人和 agent 按清单执行；
- **不存资产副本**：清单只引用名字；
- **不替代事实基线**：项目现状仍写 `docs/product/facts.md`，装配单只管「装了哪些」。
