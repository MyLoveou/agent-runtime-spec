# 素材混剪

## 何时用

- 已有一堆片段/图片，要剪成 15–90 秒的成片；
- 需要节奏（卡点）、标题、转场、背景音乐；
- 没有口播稿驱动（有口播稿走 `video-production`）。

不适用：单人讲话长视频、纯录屏讲解、逐帧动画。

## 七阶段管线

```
1 分析    扫素材，出 assets.json（时长/分辨率/场景/内容标签）
2 方案    交互式写 treatment（镜头表），用户确认后才往下
3 音乐    选情绪 → 生成/挑选 BGM → 提取 BPM 与节拍点
4 剪辑单  LLM 匹配素材到镜头 + 节拍吸附 → timeline.json（唯一真相）
5 预览    480p 预览 → 用户审批（可改 timeline 或重挑镜头）
6 标题    单独渲染带透明通道的标题层
7 合片    按 timeline 渲染：运动、转场、混音
```

顺序不能跳：**先方案后剪辑、先预览后合片**。跳过任一门，返工成本翻倍。

## 各阶段的验收

| 阶段 | 通过标准 |
|------|----------|
| 分析 | 每个素材都有时长/分辨率/内容标签；无 0 秒与损坏文件 |
| 方案 | 镜头表覆盖全部时长，每个镜头有一句话意图 |
| 音乐 | 有 BPM 与节拍点；时长 ≥ 成片时长 |
| 剪辑单 | 首尾镜头定死；每刀落在节拍 ±100ms |
| 预览 | 用户明确说「可以」才继续 |
| 标题 | 透明通道正确，无黑底 |
| 合片 | 音画同步；响度达标；无黑帧/冻帧 |

## 关键决策

1. **只动 timeline.json**：任何改剪都改这一份，不手改渲染脚本；
2. **预览门是硬门**：没有审批不进入合片，避免「渲染完发现方向错了」；
3. **标题与画面分离**：标题单独渲染成带 alpha 的层再叠，改字不用重渲画面；
4. **音乐先于剪辑**：先有 BPM，剪辑才有网格可吸；
5. **素材够不够先算**：总素材时长 < 目标时长 × 1.5 时，先补素材，别硬剪。

## 常见失败

| 现象 | 原因 | 修法 |
|------|------|------|
| 卡点「差半拍」 | 节拍点只取了整拍，没算偏移 | 用 BPM 反推帧号，再手调 ±2 帧 |
| 素材风格跳跃 | 分析阶段没做色调/场景聚类 | 按场景分组，同组连续出现 |
| 标题糊 | 直接叠在压缩后的画面上 | 标题层用高分辨率透明层 |
| 音乐盖过人声 | 没做 sidechain 压低 | 见 ffmpeg-recipes 的 ducking |
| 越剪越长 | 每个镜头都舍不得删 | 按 treatment 的镜头数硬约束 |

## 边界

- 不生成素材本身（生成交给专门的图像/视频模型）；
- 不做逐词字幕（见 `video-captions`）；
- 不做剪辑判断训练（见 `video-cut-grammar`）。
