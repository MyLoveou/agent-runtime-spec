# 口播稿

> 把「N 条数据」变成能念的稿子。开头、正文、结尾三段，结构和红线都在这里。

## 一、结构

```
开头（封面介绍卡，约 8 秒）
正文 N 条（每条 = 简介压缩 + 点评）
结尾（总结 + 坦诚说明 + 求推荐）
```

**开头和结尾单独处理，不要混进正文条目。**

## 二、开头模板（跨题材通用）

> 各位书荒的朋友大家好，今天为大家带来的是 **{主题}** 推荐，共计 **{N}** 本。

- 主题念全称，不念缩写；
- 数量用中文数字；
- 参考语速 5 字/秒：43 字 ≈ 8.6 秒，封面卡就设 8 秒。

## 三、正文规则

每条两块：

```
简介：≤2 句，按平台简介压缩，只留情节，不加形容词
评价：作者自己的短评原话
```

### 红线

1. **不写没说过的评价**——「经典开局」「量大管饱」这类如果不在点评里，就不许出现；
2. **删掉点评里的待办**（「（去找图）」「（身份后续补）」），否则会被念出来；
3. **没看过就写没看过**，不编阅读体验；
4. 简介和评价不重复，同一个梗只出现一次。

## 四、阅读状态决定口径

| 状态 | 文案口径 |
|------|----------|
| 读过 | 正常评价 |
| 翻过 | 只说开头，不评整体 |
| 只知道 | 只写客观信息（字数 / 状态 / 简介），或「评论区说…」 |
| 没看过 | 不推，或明说没看过 |

这条是「不编造」的落地方式：状态决定能说多少。

## 五、结尾结构

1. 题材总结（一句玩梗收束）；
2. 坦诚说明（「有的行文一般，只是对题材感兴趣」）；
3. 平台现状 + 求推荐（换平台、求补充）；
4. 结束语。

## 六、时长估算

- 语速按 **5 字/秒**；
- 19 条正文（每条 60–80 字）+ 开头结尾 ≈ 4.5–5 分钟；
- 估算只用于草稿片；录音后按 `配音清单_实际.csv` 回填真实时长。

## 七、常见返工

| 现象 | 原因 | 修法 |
|------|------|------|
| 「AI 味」重 | 评价是生成的，不是作者的话 | 评价段全换成原话，简介压到 2 句内 |
| 开头结尾太长 | 和正文混在一起写 | 拆出去单独处理 |
| 念出来别扭 | 长句、书面语 | 改成短句、口语，一句一个信息 |
| 时长超了 | 按估算排的时间轴 | 用实测秒数重排 |

## 八、自检

- [ ] 每条都有「简介 + 评价」两块，没有单独一块的
- [ ] 评价全部来自点评原话，无编造形容词
- [ ] 无残留待办括号
- [ ] 开头念全称、数量用中文数字
- [ ] 结尾四要素齐全
- [ ] 总字数 ÷ 5 与目标时长相差 < 15%
