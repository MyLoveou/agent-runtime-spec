
# 交付后的经验总结

本项目由 AI 执行，但读者是人。**每次交付完成后，写一条经验笔记**，把这次做法的原理讲清楚。

## 触发

功能、修复、重构、运维动作完成时（不是每次对话，是每次「做完了」）。

## 最低要求

- 位置：项目 `docs/经验总结/`，文件名 `<两位序号>-<类型>-<主题>.md`
- 类型前缀：`踩坑` / `技术` / `设计` / `学习向` / `图解`
- 序号连续，不跳号、不覆盖旧文件

## 一条笔记必须包含

1. **结论先行**：第一段说清「解决了什么、用什么思路」
2. **原理**：为什么这样做；还有哪些替代做法，为什么没选；边界在哪
3. **可验证**：给读者一个能自己跑、自己看、自己改的最小实验或对照
4. **延伸**：一条进一步学习的方向（概念 / 文档 / 源码入口）

## 红线

- 不复述代码逐行解释（读者能读代码）
- 不写「学习了」「收获很大」这类空话
- 不编造没验证过的机制；不确定就写「未验证」
- 不把内部黑话当结论（先给一句人话，再给术语）

## 交付时

在最终回复末尾附：**笔记路径 + 一句话知识点**。

细则与模板见 `skills/learning-notes/SKILL.md`。
