# 设计 · 单层运行时包（`.cursor` / `.opencode` / `.dsh`）

> 状态：**待确认**（L2 设计，未获确认不动文件）
> 决策来源：D1 三平台（Cursor + OpenCode + DeepSeek Harness）；D2 删除域包；D3 删除脚本；D4 根 `AGENTS.md` 共用
> 本文只给设计与迁移契约；`需求.md` 的要点即下一节「目标」。

---

## 1. 目标

把现在「源目录 + 生成脚本 + 部署脚本」的三层结构，压成「**每平台一个自包含顶层目录**」。

三条验收口径：

1. 只拷 `.cursor/` 到任意项目 → 规则、Agent、Skill、hook、MCP 全部可用；
2. 只拷 `.opencode/` → instructions、agent、skill、mcp 全部可用；
3. 只拷 `.dsh/skills/` → DSH 项目级 Skill 全部可用。

不再有 `shared/`，不再有生成与同步，不再有域包。

---

## 2. 设计原则

1. **一平台一目录，目录内闭环**：任何跨顶层目录的引用都算缺陷。
2. **正文平台中立，包装层分叉**：同一资产的三份副本，去掉 frontmatter 后必须逐字节一致；差异只允许出现在 frontmatter 与文件扩展名。
3. **不设抽象层**：没有 `shared/`、没有模板目录、没有再生成。
4. **单一入口**：只有根 `AGENTS.md` 是跨平台文件；三平台原生都读它。
5. **删除优先于保留**：域包、扫描器、模板目录一律退场，需要时从 git 历史取。

**拷贝单元**（写进 README）：

| 目标平台 | 必拷 | 建议同拷 |
|----------|------|----------|
| Cursor | `.cursor/` + `AGENTS.md` | `docs/` 骨架 |
| OpenCode | `.opencode/` + `AGENTS.md` | `docs/` 骨架 |
| DSH | `.dsh/` + `AGENTS.md` | `docs/` 骨架 |

单拷平台目录能跑，但入口文档与项目事实基线在根目录，故定义为「目录 + AGENTS.md + docs」。

## 4. 三平台能力矩阵（决定每个目录放什么）

| 资产 | Cursor | OpenCode | DeepSeek Harness |
|------|--------|----------|------------------|
| 规则 | **原生** `.mdc`，支持 `globs`/`alwaysApply` 选择性注入 | 经 `opencode.json.instructions` 载入，**全量注入、无 globs** | **不支持**，只有 `AGENTS.md` |
| Agent | 原生 `.cursor/agents/*.md` | 原生 `.opencode/agent/*.md`（`mode: subagent/primary`） | 不支持（preset 在 `~/.dsh`） |
| Skill | `.cursor/skills/` | `.opencode/skills/` | **`.dsh/skills/`（项目级最高优先级 100）** |
| 命令 | 无 | `.opencode/command/*.md` | 内置命令，无文件入口 |
| 工作流/评测 | 纯文档目录 | 纯文档目录 | 纯文档目录（无效） |
| Hooks | `hooks.json` 注入 prompt | 需写 TS plugin，语义不同 | 无 |
| MCP | `mcp.json`（`mcpServers`） | `opencode.json` 的 `mcp`（`type: local`，`command` 为数组） | 只有全局配置，无项目级 |
| 硬约束 | `constraints.md` | `constraints.md`（进 instructions） | 并入 `AGENTS.md` |

结论：`.dsh/` 只承载 Skill；DSH 侧的规则等效物只有根 `AGENTS.md` 的摘要与 Skill 内文。这一点必须写进 `.dsh/README.md`，避免以后误以为「拷了 .dsh 就有全部规则」。

## 6. 正文去平台化（一次性改写）

现状：`rules/`＋`shared/` 里 **60 处 `.cursor/`、11 处相对 `skills/`、5 处 `shared/`** 写死在正文。若原样复制，OpenCode/DSH 副本会指向不存在的路径。

规则：

1. 正文**禁止**出现 `.cursor/`、`.opencode/`、`.dsh/` 前缀；
2. 一律改成相对平台根的写法：`rules/<name>`、`skills/<name>/SKILL.md`、`workflows/<name>.md`；
3. 需要强调平台时写「本平台目录下 ……」；
4. **例外**只有根 `AGENTS.md`——它是入口，必须列出三个真实路径。

示例：

```
- 先读 `.cursor/skills/project-spec/SKILL.md`
+ 先读本平台目录下 `skills/project-spec/SKILL.md`
```

这条约束是「三份正文逐字节一致」的前提，也是以后唯一可机械校验的一致性指标。

## 7. OpenCode 注入策略（不能照搬 42 条）

OpenCode 的 `instructions` 是**全量注入**，没有 `globs`/`alwaysApply`。42 条规则全塞进去 ≈ 每次会话多 15k tokens。

`.opencode/opencode.json` 只放入口级文件：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "AGENTS.md",
    ".opencode/constraints.md",
    ".opencode/rules/project-core.md",
    ".opencode/rules/ai-execution.md",
    ".opencode/rules/workflow-triggers.md",
    ".opencode/rules/openspec.md"
  ],
  "mcp": { "...": "codegraph / git / ssh，结构按 OpenCode schema" }
}
```

其余 36 条留在 `.opencode/rules/`，由 `AGENTS.md` 的索引按需读取——与 Cursor 的「alwaysApply + globs」是两种语义，必须在 README 里讲明，不能假装等价。

> 待实测：`instructions` 的相对路径基准（项目根 vs `.opencode/`）。实施第一步用 `opencode debug config` 验证后再定稿。
