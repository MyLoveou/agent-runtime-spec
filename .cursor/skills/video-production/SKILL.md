# 推荐类长视频生产

## 何时用

- 一期推 **10** 个条目（书 / 游戏 / 产品），成片 3–6 分钟；
- 视觉模板固定（开场、卡片、字幕、BGM），内容只换数据；
- 需要出 4K + 1080p 两档。

不适用：真人出镜、纯剪辑、逐帧动画短片。

## 九步流水线

| # | 步骤 | 需要什么能力 | 何时需要 | 产出 |
|---|------|--------------|----------|------|
| 1 | 选题 | 候选池 + 去重（剔掉做过的） | 开工前 | 条目清单 |
| 2 | 开工检查 | 读断点、给出下一步 | 每期开始 | 工作记录 |
| 3 | 采集元数据 | 按书名批量抓元数据与封面，带相似度匹配 | 清单定稿 | 元数据 json |
| 4 | 清洗 | 去标签块、作者注、求票尾巴 | 采集后立刻 | 清洗版 json |
| 5 | 封面处理 | 超分 → 统一画布（cover）→ 去水印 → 转 JPG | 采集后 | 统一封面图 |
| 6 | 写点评 | 逐条人工 / 半自动点评 | 封面就绪 | 点评 json |
| 7 | 口播稿 | 简介压缩 + 点评原话 | 点评定稿 | 口播稿 |
| 8 | 配音与字幕 | ASR 定位切点、切片、字幕对齐 | 稿定稿 | wav + 清单 + 字幕 |
| 9 | 渲染与归档 | 4K / 1080p 渲染、归档 | 全部就绪 | 成片 |

「需要什么能力」只描述**能力**，不绑定脚本；选型与替代方案见 [references/infra.md](references/infra.md) 与各环节 references。

## 四条设计决定（改架构前先读）

1. **数据与渲染分离**：合成数据由脚本生成成 JSON，Remotion 只读不写；改数据不动模板。
2. **单集隔离**：每期素材放 `ep/<主题>/`，数据存 `episodes/<主题>.json`，字幕按集注入。否则旧素材残留、Studio 越开越慢、字幕串期。
3. **草稿模式**：先按固定时长（如每条约 9 秒）出结构片，录音后再用**实际时长**回填；不要用估算值出成片。
4. **动效纪律**：图片入场 ≤1 秒，落位后完全静止；禁止 Ken Burns、禁止 spring 过冲。详见 [references/motion.md](references/motion.md)。

## 每期条目数与选题单位（2026-11 调整）

- **每期 10 个条目**（原 15–30）。原因：可用书目远少于库存，28 本/期只够做 5–10 期；
- **选题单位是「角度」，不是「题材」**。题材只是角度的一种，且会耗尽；
- 角度类型：题材 / 设定 / 情绪 / 平台 / 时间 / 个人（「我最近在看的 10 本」兜底）；
- 角度可复用（Vol.2、Vol.3），**书目不得重复**，用跨期台账（`已用书目.json`）约束；
- 目录命名 `<日期>-<角度简称>`，不强制带「主题」二字。

判据：**宁可 10 本讲透，不要 28 本凑数**。每本 12 秒能把「为什么好」说清楚，
每本 8 秒只能念简介。

## 一期一目录

```
<期目录>/
├─ readme.md          # 内容结构：条目、开头、BGM、总结
├─ 工作记录.md         # 断点：已完成 / 待办
├─ 素材/
│  ├─ 封面/ 封面_超分/ 封面_统一/
│  ├─ 音频/ voice/ 音频/ BGM/
│  ├─ 成片/            # 4K 与 1080p
│  └─ 元数据.json 元数据_清洗.json 点评.json
├─ 文案/ 完整口播稿.md 配音清单.csv 配音清单_实际.csv subtitles.json
└─ 相关/ 清单.txt 资料.md 链接.md
```

## 验收（每期必过）

- [ ] 条目数、时长与稿件一致；时间轴用 `配音清单_实际.csv` 的实测秒数，不用估算
- [ ] 字幕与口播同句：抽开头 / 中段某条 / 结尾三点核对
- [ ] 封面四角无白边、无残留水印
- [ ] 卡片落位后完全静止（无缩放、无漂移）
- [ ] 关掉片头时尾部没有黑屏（总帧数记得减片头时长）
- [ ] 4K 与 1080p 内容完全一致，只是分辨率不同

## 边界

- **版权**：官方素材用于同人向二次创作属常见做法，但未获授权；商用、原样搬运有风险，素材来源要留痕。
- **不编造**：没有的阅读/使用体验就写没有，点评必须是作者原话（见 [references/copywriting.md](references/copywriting.md) 红线）。
- **不做判断**：选题价值、平台合规由人定；本技能只负责把已定的内容做成片。
- **不打包脚本**：本技能只写到「需要什么能力、什么时候要」，具体实现按项目环境自选。
