# 管线细节与产物

## 产物与依赖

| 阶段 | 产物 | 来源 | 下一阶段依赖 |
|------|------|------|--------------|
| 分析 | `assets.json` | 扫描素材目录 | 方案 |
| 方案 | `treatment.yaml` | 人 + 模型 | 剪辑单 |
| 音乐 | `bgm.*` + `bgm_meta.json`（BPM/节拍点） | 生成或选曲 | 剪辑单 |
| 剪辑单 | `timeline.json` | 素材匹配 + 节拍吸附 | 预览/合片 |
| 预览 | `preview.mp4`（480p） | 按 timeline 快渲 | 审批 |
| 标题 | `titles/*.mov`（带 alpha） | 单独渲染 | 合片 |
| 成片 | `final.mp4` | 合成 | 交付 |

中间产物**全部保留**：改一版只重跑受影响阶段，不从头来。

## 1 分析

扫描每个素材：时长、宽高、帧率、旋转、是否有音轨、内容标签（场景/人物/风格）。

- 用 `ffprobe` 取客观参数，用视觉模型取内容标签；
- 标记不可用素材（0 秒、分辨率过低、全黑）；
- 输出按内容聚类，方案阶段才能排「同类连排」。

## 2 方案（treatment）

把 brief 变成镜头表：每个镜头写清「用什么素材、说什么、多长、什么情绪」。

要点：

- 镜头数由目标时长与节奏定（快剪 1–2 秒/镜头，叙事 3–6 秒）；
- 每个镜头必须有**意图**（交代/过渡/高潮/收尾），说不出意图的镜头删掉；
- 方案未确认前不碰 timeline。

## 3 音乐

- 先定情绪（3 个候选让用户选），再定曲；
- 曲定后提取 BPM 与节拍时间点，写进 `bgm_meta.json`；
- 没有生成能力时，从曲库选，同样要提 BPM。

## 4 剪辑单（EDL）

把镜头表落到具体素材与时间：

```jsonc
{
  "fps": 30,
  "duration": 32.5,
  "tracks": [
    { "id": "v1", "clips": [
      { "src": "media/a.mp4", "in": 2.0, "out": 5.2, "at": 0.0, "motion": "kenburns-in" }
    ]},
    { "id": "music", "src": "bgm.mp3", "volume": -18, "duck": true }
  ],
  "titles": [ { "text": "标题", "at": 0.5, "dur": 2.0, "layer": "titles/t1.mov" } ]
}
```

规则：

- 所有时间以秒记，渲染时按 fps 换算帧；
- 每刀对齐节拍，允许 ±100ms 微调，超出就换素材；
- 同一素材不重复使用超过两次（除非刻意的回环）；
- 首镜头与末镜头最后定，先定中间。

## 5 预览门

480p、低码率、快速编码，目的是**看结构**不看画质。

审批时只问三件事：

1. 节奏对不对（快了/慢了）；
2. 素材选得对不对（有没有更合适的）；
3. 标题与收尾是否成立。

改法：直接改 `timeline.json` 再重渲预览；不重跑分析与方案。

## 6 标题层

- 单独渲染为带 alpha 的序列（ProRes 4444 或 WebM alpha）；
- 字号按画面高度比例算，换分辨率不失真；
- 标题入场 ≤0.5 秒、之后静止（与 `video-production` 的动效纪律一致）。

## 7 合片

按 timeline 一次渲染：裁切/缩放 → 运动（Ken Burns）→ 转场 → 叠标题 → 混音 → 编码。

- 先出 1080p 审片，再出目标分辨率；
- 响度统一到平台标准（见 ffmpeg-recipes）；
- 输出后抽帧核对：首帧、每个转场、末帧。

## 重跑矩阵

| 改了什么 | 重跑 |
|---|---|
| 换素材 | 分析 → 方案（局部）→ 剪辑单 → 预览 → 合片 |
| 调节奏 | 剪辑单 → 预览 → 合片 |
| 换音乐 | 音乐 → 剪辑单（节拍吸附）→ 预览 → 合片 |
| 改标题 | 标题 → 合片 |
| 调色 | 合片 |
