# 短视频脚本

## 先定三件事

1. **一条主张**：整条视频只讲一件事，讲不清就拆成两条；
2. **一个观众**：写给谁（他自己会怎么描述这个痛点）；
3. **一个动作**：看完要他做什么（关注 / 收藏 / 点链接 / 记住一句话）。

三个没定，别写正文。

## 结构

```
0–3s    钩子：反常识 / 具体数字 / 直接点名痛点
3–8s    承诺：这条视频给什么（可验证，不吹）
8–N    正文：3–5 个节拍，每拍一个信息点
最后 5s 收尾：回扣主张 + 一个动作
```

**总时长 = 字数 ÷ 语速**。中文口播按 5 字/秒，30 秒 ≈ 150 字。

## 钩子的四种写法

| 类型 | 例子（结构，不是文案） |
|------|------------------------|
| 反常识 | 「越 X 越 Y」——先否定常见做法 |
| 具体数字 | 「我用 3 天省了 4000 块，方法是…」 |
| 点名痛点 | 「如果你也遇到过 X，这条一定要看」 |
| 悬念 | 「最后一步我差点放弃」 |

同一主题写 5 条钩子，挑一条；不要第一条就用。

## 节拍表（beat sheet）

```yaml
beats:
  - id: 1
    role: hook
    text: "<钩子>"
    seconds: 3
    visual: "<画面/镜头提示>"
  - id: 2
    role: promise
    text: "<承诺>"
    seconds: 5
    visual: "<画面>"
  - id: 3
    role: point
    text: "<信息点>"
    seconds: 8
    visual: "<画面>"
```

规则：

- 每个节拍一个信息点，两个信息点就拆两拍；
- 每拍有画面提示，不能只有台词；
- 节拍总时长与目标时长差 < 10%。

## 口播轨的写法

- 短句：一句一个信息，超过 25 字就断；
- 口语：念出来像说话，不像稿子（写完读一遍，卡住的地方重写）；
- 具体：用数字、名词、场景，不用「非常」「很多」「各种」；
- 去 AI 味：删掉「首先/其次/综上所述/值得注意的是」这类连接词。

## 镜头脚本

| 节拍 | 画面 | 景别/机位 | 时长 |
|------|------|-----------|------|
| 1 | 人物近景直视镜头 | 近景 | 3s |
| 2 | 手部操作特写 | 特写 | 5s |
| 3 | 屏幕/产品全貌 | 中景 | 8s |

镜头清单要能直接拍：每行写清「拍什么、怎么拍、拍多久」。

## 验收

- [ ] 只看前 3 秒，能说出这条视频讲什么
- [ ] 全文只有一条主张
- [ ] 每拍一个信息点，无重复
- [ ] 字数 ÷ 5 与目标时长差 < 10%
- [ ] 结尾有明确动作
- [ ] 读一遍没有拗口句

## 与其它技能的分工

- 要剪现成素材 → `video-compose`
- 要逐词字幕 → `video-captions`
- 要判断剪辑点 → `video-cut-grammar`
