# 多仓协同

单仓改动不用本技能。跨仓（≥2 个仓）时按顺序走。

## 三个角色

| 角色 | 做什么 | 有子代理时 | 没有时（如 DSH） |
|---|---|---|---|
| 巡检 | 只读采集各仓状态 | 委派 `repo-surveyor` | 自己跑命令 |
| 导出 | 按装配单写目标仓 | 委派 `exporter` | 自己跑 `assemble.ps1` |
| 笔记 | 先搜后写、迁移与索引 | 委派 `note-curator` | 自己按 `learning-notes` 做 |

## 六步

| # | 步骤 | 关键动作 | 门禁 |
|---|---|---|---|
| 1 | 巡检 | 分支 / 脏数 / 未推 / remote / temp 挂载 / 闸门 | 脱管或脏仓先标红 |
| 2 | 定范围 | 这次动哪几个仓、先后顺序 | 用户确认后再动手 |
| 3 | 导出 | 先 `-DryRun` 看 `copied/same/diff`，再执行 | 不加 `-Force`；diff 要说明 |
| 4 | 笔记 | 搜索 → 判断 → 新建或合并 | 同结论只有一条 |
| 5 | 本库发版 | 分支 → 合并 → tag → 推送 | `spec-check` 绿、CI success |
| 6 | 业务仓收尾 | 各仓独立 commit / push | 不代推别人的 WIP |

## 巡检要采集什么

| 字段 | 判据 |
|---|---|
| 分支 | `HEAD` = 脱管，**不能直接动** |
| 脏文件数 | 多则只读，先读差异再判断 |
| 未推送提交 | 大于 1 时先确认是不是别人的 |
| remote | 没有 remote 的仓本地提交即可，不要「推送失败」当异常 |
| temp 挂载 | 必须是 `Junction`；普通目录或缺失说明没统一 |
| 闸门 | 有 `spec-check` 的仓先跑，红的不动 |

## 并行边界

- 巡检与整理笔记可并行（只读 / 只动 temp）；
- 导出必须串行：一仓失败就停；
- 本库发版与业务仓提交互不阻塞。

## 失败分支

| 现象 | 处理 |
|---|---|
| 仓处于 `HEAD` | 停下，报告；不要擅自 checkout / reset |
| `-DryRun` 出现 diff | 列清会被覆盖的文件，等确认 |
| 导出后数量不符 | 查装配单是否漏项，别重试 |
| temp 历史分叉 | 先合流再继续（单 clone + junction 的约定见 `learning-notes`） |
| 推送被拒 | 先看是不是别人的未完成提交 |

## 红线

- 不 `stash` / `reset` / 强推
- 不替用户提交业务仓
- 不在脏仓上做覆盖式导出
- 多仓改动必须逐仓报告，不合并结论

## 验收

- [ ] 每个仓都有「改了什么 / 提交号 / 是否推送」
- [ ] 本库闸门绿、tag 已推
- [ ] temp 的改动已提交并推送
- [ ] 没有把别人的未完成提交一起推出去
