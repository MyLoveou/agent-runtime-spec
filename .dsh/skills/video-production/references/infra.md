# 可选后端：infra

> 本技能**不依赖** infra 也能跑：这里只说明「已有能力就别重复造」，以及没有 infra 时的替代方案。

## 一、判断顺序

1. 先问：这个能力是**通用底层能力**吗（超分、格式转换、去水印、抓元数据）？
   - 是 → 优先用现成工具（同机若有 infra 就直接调，没有就选等价工具）；
   - 否（本技能特有的编排：统一画布 cover、切片、时间轴）→ 自己写。
2. 再问：现成工具缺哪一步？——只补缺的那一步，不要重写整条链。

## 二、能力对照

| 需要的能力 | 有 infra 时 | 没有 infra 时 |
|------------|-------------|----------------|
| 图片超分 | `infra.media images --engine waifu2x --scale 4 --profile anime` | waifu2x / realesrgan 的独立 CLI |
| 图像修复 / 锐化 | `infra.media repair --sharpen` | 同类修复模型 CLI |
| 格式转换（含去元数据） | `infra.media convert --to jpg --quality 95 --strip` | ImageMagick / PIL |
| 去水印（局部修补） | `infra.watermark image --rect x1,y1,x2,y2 --backend lama-onnx --model-dir …` | LaMa 同族模型，或裁切/换源 |
| 条目元数据采集 | `infra` 的平台适配器（搜索 + 详情） | 自写抓取，或人工整理 |
| 简介清洗 | 暂无稳定入口（曾提需求） | 自写规则清洗 |

调用形态两选一：**子进程调 CLI**（简单、隔离）或**模块导入**（快、要版本对齐）。二选一后写进项目 README，别两套并存。

## 三、已知缺口（用的时候要补）

| 缺口 | 说明 | 现状 |
|------|------|------|
| 固定画布裁切 | 通用缩放只有 resize，没有「统一到 WxH 并 cover 裁切」 | 自己实现（`max` 缩放 + 居中裁切），或提给 infra 加 `fit --canvas --mode cover` |
| 简介清洗 | 平台简介带标签块 / 作者注 / 求票尾巴 | 规则清洗，见 [acquisition.md](acquisition.md) |
| 平台状态语义 | 个别平台连载/完结字段与直觉相反 | 接入时人工核对，见 [pitfalls.md](pitfalls.md) |

## 四、接入纪律

- **可选，不硬依赖**：没有 infra 时整套流程仍能跑，只是要自己选等价工具；
- **不要复制实现**：超分、去水印这类底层能力，包装一层调用即可，别在项目里再写一份；
- **参数化**：项目里调用时把根目录、题材、画布尺寸做成参数，不写死路径；
- **发现缺陷回补**：在项目里临时修的平台适配 bug，要回到工具侧修 + 加测试，否则下次还会踩。

## 五、怎么确认本机有没有

```powershell
python -c "import infra, sys; print(infra.__file__)"   # 能导入说明装了这个包
```

导入失败就按「没有 infra」那一列选替代方案，不要在流程里留一个必挂的依赖。
