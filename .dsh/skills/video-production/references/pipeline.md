# 流水线编排

> 从「只有一份书名清单」到「两份成片」的完整顺序、断点与节奏控制。

## 1. 目录与断点

一期一个目录，目录名带日期与主题：

```
<分类>/<YYYY.MM.DD>-<主题>/
```

目录内固定四块：`素材/`、`文案/`、`相关/`、`工作记录.md`。`工作记录.md` 只记两件事：**已完成**、**下一步**；中断后从它恢复，不靠回忆。

## 2. 九步与依赖关系

```
选题 ──▶ 采集 ──▶ 清洗 ──▶ 封面 ──▶ 点评 ──▶ 口播稿 ──▶ 配音 ──▶ 渲染 ──▶ 归档
                 └──────┴─ 都可以在封面就绪前并行
```

- **采集 / 清洗**可批量做，先把元数据做全，再进封面；
- **点评**必须逐条过，别批量生成（见 copywriting 的红线）；
- **口播稿**依赖点评定稿；**配音**依赖稿件定稿；**渲染**依赖实测时长；
- **归档**是最后一步，做完再改目录名，避免路径失效。

## 3. 草稿模式（先看结构，再录音）

1. 按固定时长（每条 9 秒左右）出一次草稿片，只看结构、节奏、卡片排布；
2. 结构确认后再录配音；
3. 录音完成，用实测秒数回填，出正式片。

好处：改结构的成本 ≪ 重录的成本。**不要跳过草稿直接录音。**

## 4. 渲染与归档顺序

1. 停掉预览服务（Studio 类工具会占端口，导致程序化渲染抓错页面）；
2. 出数据（只生成 JSON，不渲染）先验一遍时长总和；
3. 渲染 1080p 审片版 → 看一遍 → 再渲染 4K；
4. 归档：移动到归档盘并更新索引，目录名加完成标记。

耗时参考（24 核、卡片式 4K）：7 分钟成片约 25–30 分钟；1080p 审片版 5–8 分钟。

## 5. 最小可行骨架（新项目复用）

只需要四件东西，其余都是可替换细节：

1. 一个模板工程（固定视觉 + 读一份 JSON）；
2. 一个数据生成脚本（元数据 → 合成数据）；
3. 一个渲染包装（两条命令：出数据、渲染两档）；
4. 一个归档脚本（移动 + 索引）。

## 6. 排期建议

| 阶段 | 占时比 | 易超时的地方 |
|------|--------|--------------|
| 采集 + 清洗 | 20% | 平台风控、书名变更 |
| 封面处理 | 15% | 水印、比例不符、超分引擎选择 |
| 写稿 + 点评 | 30% | 「AI 味」返工、点评缺失 |
| 配音 + 字幕 | 20% | 切点识别、字幕累积偏移 |
| 渲染 + 归档 | 15% | 端口冲突、素材体积过大 |
